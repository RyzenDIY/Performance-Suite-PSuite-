# 🗒 Реєстр Технологій Обходу Античиту Easy Anti-Cheat (EAC)
*Версія: 2026.4 (Ультимативна збірка з витоками метаданих)*

---

## 🟢 Категорія 1: Апаратні методи (Hardware-level)
Найбільш живучі та ізольовати підходи, де логіка виконання винесена за межі видимості ОС Windows.

* **DMA-карти (Direct Memory Access)**
  - *Суть:* Фізична плата в PCIe-слоті ігрового ПК (ПК-1) зчитує ОЗУ напряму через залізо шини.
  - *Реалізація:* Дані передаються через USB-кабель на 2-й («чистий») комп'ютер (ПК-2), де працює сам чит та малюється радар/ESP.
  - *Захист від детекту:* Потребує унікальної індивідуальної прошивки (Custom Firmware), яка маскує пристрій під легальну мережеву або звукову карту.

* **Програмна імба: Ізоляція через Linux (WSL2 / Hyper-V MMIO)**
  - *Суть:* Використання офіційної підсистеми Windows для Linux (WSL2).
  - *Реалізація:* Графічна оболонка Linux працює на базі полегшеного гіпервізора Hyper-V та має легальний апаратний доступ до фізичної пам'яті комп'ютера через технологію MMIO (Memory-Mapped I/O). Чит запускається всередині ядра Linux і зчитує пам'ять Windows-процесу гри ззовні.
  - *Захист від детекту:* Висока ефективність, оскільки EAC працює всередині Windows і не може напряму сканувати процеси чи пам'ять ізольованого ядра Linux.

* **Кастомні гіпервізори (Ring -1 / VMM)**
  - *Суть:* Створення власної мікро-ОС (VMM), що запускається до старту самої Windows через UEFI-завантажувач.
  - *Реалізація:* Windows та EAC завантажуються всередині цієї віртуальної машини. Чит контролює залізо і зчитує пам'ять ззовні через розширені таблиці сторінок (EPT/NPT), підміняючи сторінки коду для anti-cheat "на льоту" (Shadow Pages).
  - *Захист від детекту:* Вимагає ідеального маскування таймінгів виконання інструкцій процесора (обхід обчислювальних затримок на `VM-Exit` / `RDTSC`).

* **Режим системного керування (SMM / Ring -2)**
  - *Суть:* Код вбудовується безпосередньо в BIOS/UEFI материнської плати.
  - *Реалізація:* Процесор періодично переходить у режим SMM для обслуговування заліза, повністю заморожуючи Windows та EAC на наносекунди. У цей момент чит зчитує координати.

## 🟡 Категорія 2: Розумні програмні обходи (Рівень Ядра / Ring 0)
Методи, що працюють всередині Windows, але використовують легальні лазівки або системні дірки для маскування драйвера чита.

* **BYOVD (Bring Your Own Vulnerable Driver)**
  - *Суть:* Завантаження коду в простір ядра через офіційно підписані драйвери сторонніх виробників.
  - *Реалізація:* Використовується старий легальний драйвер (наприклад, утиліти безпеки або розгону від ASUS, MSI, Gigabyte), який має сертифікат Microsoft, але містить критичну вразливість, що дозволяє читу виконати свій код у Ring 0.
  - *Захист від детекту:* Вимагає постійного пошуку нових, ще не занесених до чорних списків (Blocklist) EAC вразливих драйверів.

* **Крадені або приватні цифрові сертифікати**
  - *Суть:* Підпис драйвера чита діючим сертифікатом легальної компанії-розробника.
  - *Реалізація:* Сертифікати купуються на чорному ринку. Для EAC такий драйвер виглядає як довірений системний процес або офіційне оновлення софту.

* **Kernel Callback Injection (Модернізовані гачки Windows)**
  - *Суть:* Впорскування коду чита безпосередньо в легальні системні структури зворотних викликів ядра Windows.
  - *Реалізація:* Модифікація таблиць викликів (`KernelCallbackTable` у PEB або структури `win32k.sys`). Код чита викликається самою операційною системою під час стандартних процедур (рух миші, оновлення вікон графічної підсистеми GDI, повідомлення `WM_COPYDATA`).

## 🔵 Категорія 3: Зовнішній аналіз (User Mode / Ring 3)
Програми, які не взаємодіють з оперативною пам'яттю гри та її кодом напряму, тому захищені від класичних сигнатурних детекту.

* **Нейромережі та комп'ютерний зір (AI / CV)**
  - *Суть:* Автономний скрипт (зазвичай на Python), що аналізує відеопотік з екрана клієнта.
  - *Реалізація:* Модель (наприклад, YOLO) знаходить силуети персонажів або підсвічені хитбокси і вираховує координати для автоматичного наведення. Палиться поведінковим аналізом на боці сервера.
  - *Просунутий UI:* ШІ може працювати в парі з повністю чистим, прозорим вікном-накладенням (Overlay Windows). Він аналізує картинку, знаходить ворогів і самостійно малює рамки (Boxes) на твоєму екрані, створюючи повноцінне ВХ без читання ОЗУ.

* **Апаратна充емуляція миші без затримок (Raspberry Pi Pico / RP2040)**
  - *Суть:* Використання мікроконтролерів для надсилання команд введення.
  - *Реалізація:* Потужний двоядерний чіп ARM (133 МГц) із вбудованим контролером DMA. Дані від ШІ-чита залітають з USB-порту в пам'ять контролера миттєво через наскрізний канал (Passthrough), взагалі минаючи процесор плати.
  - *Переваги:* Забезпечує чесну частоту опросу 1000 Гц (відгук 1 мс). Рухи виходять ідеально плавними, без людського чи роботоподібного посмикування (джиттеру), що повністю обходить поведінковий аналіз EAC. Обов'язковий спуфінг Vendor ID / Product ID (VID/PID) під реальну мишку.

* **Звукові чити (Audio-based Hacks)**
  - *Суть:* Перехоплення та аналіз 3D-аудіопотоку звукової карти Windows.
  - *Реалізація:* Алгоритм прораховує напрямок та відстань до ворога на основі звуку кроків або пострілів, виводячи радар на екран.

## 🔴 Категорія 4: Перехоплення легальних ресурсів системи
Зловживання процесами та модулями, які за замовчуванням мають високий рівень довіри від античиту.

* **Overlay Hijacking (Викрадення оверлеїв)**
  - *Суть:* Чит не створює власне вікно для відображення ВХ (ESP).
  - *Реалізація:* Код читу впроваджується в легальний оверлей (Discord, Steam, GeForce Experience або RivaTuner) і перехоплює функцію рендерингу `Present` в DirectX, змушуючи його малювати рамки навколо ворогів.

* **Локальний веб-радар (Local HTTPS Radar)**
  - *Суть:* Робота з мережевими пакетами замість пам'яті комп'ютера.
  - *Реалізація:* Чит перехоплює ключі шифрування трафіку в момент старту гри, розшифровує координати з пакетів сервера і транслює карту на локальний веб-сайт, який гравець відкриває на будь-якому іншому пристрої.

* **Обхід через Спільну Пам'ять (Shared Memory sections)**
  - *Суть:* Підключення до транзитних зон комунікації Windows.
  - *Реалізація:* Чит знаходить у системі відкриті легальні секції пам'яті Windows (`CreateFileMapping` з прапорцем `SEC_COMMIT`), які гра створює для комунікації з іншим софтом (голосові чати, лаунчери, Steam). Чит "підслуховує" цей спільний буфер, витягуючи технічні дані без прямого контакту з грою.

* **Метод «Некромантія» (Suspended Process Hijacking)**
  - *Суть:* Маніпуляція з логікою перевірки запущених програм.
  - *Реалізація:* Чит запускає легальну програму Windows (наприклад, Блокнот) у замороженому стані (`CREATE_SUSPENDED`). Після цього підміняє її код на свій. Процес виглядає як легальний `notepad.exe` і перебуває в глибокому сні. Він прокидається на мікросекунду лише для того, щоб зробити швидкий знімок даних гри, і знову засинає, не привертаючи уваги EAC під час сканування активних потоків.

* **Примусовий аналіз зліпків (Crash Dump Windows API)**
  - *Суть:* Використання офіційної системної функції `MiniDumpWriteDump`.
  - *Реалізація:* Чит примусово робить миттєвий «зліпок» оперативної пам'яті гри, доки вона спокійно працює. Гра продовжує функціонувати, а чит аналізує створений файл-дамп на диску. Метод повністю безпечний для читання статичних даних (створення карт луту чи радарів), але занадто повільний для динамічного Аїмботу.

## 🔥 Категорія 5: Обходи через витік легальних метаданих та "цифрові крихти" гри
Елітна категорія обходів, де чит взагалі не взаємодіє з ОЗУ чи графічним ядром гри, а збирає легальні «цифрові відходи» та офіційні API, які гра сама викидає в систему. Повністю відсутній ризик детекту з боку EAC.

* **Перехоплення текстового каналу Rust+ (Rust Plus API)**
  - *Суть:* Робота через офіційний мобільний додаток від Facepunch.
  - *Реалізація:* Чит маскується під твій мобільний телефон, підключаючись до офіційного Rust+ API за допомогою унікального токена користувача.
  - *Переваги:* Сервер гри сам надсилає через веб-сокети повну мапу поточного сервера в реальному часі. Чит виводить її як повноцінний веб-радар, де видно твою базу, статус дверей, рейд-оповіщення та точні координати твоїх тіммейтів.

* **Тимчасові файли Графіки (Shader Cache / Текстурний флуд)**
  - *Суть:* Моніторинг кешу шейдерів відеокарти на SSD.
  - *Реалізація:* Кони в радіусі рендеру (~200 метрів) з'являється ворог, гра підвантажує унікальний шейдер його екіпірування чи кастомного скіна. Windows скидає копію скомпільованого файлу в Shader Cache (Nvidia/AMD або DirectX). Чит моніторить оновлення цієї папки.
  - *Переваги:* Як тільки у файлі з'являється мітка чужого скіна, софт видає сигнал: *«Увага! Поруч з'явився чужинець у металевому сеті»*.

* **Аналіз мережевого звуку (Vivox / Audio API Panorama)**
  - *Суть:* Робота з вбудованим голосовим чатом (Proximity Voice).
  - *Реалізація:* Чит підключається до аудіо-сесії голосового рушія гри через Core Audio API Windows. Оскільки звук у грі є 3D-орієнтованим, звукова карта отримує математичні коефіцієнти панорами (різницю децибел між каналами).
  - *Переваги:* Чит зчитує ці аудіо-коефіцієнти прямо з мікшера Windows і за формулою вираховує точний напрямок на ворога, який щось сказав у мікрофон, працюючи як апаратний ехолокатор.

* **Аналіз логів бойових дій (Combat Log Parsing)**
  - *Суть:* Читання живих текстових звітів Unity.
  - *Реалізація:* Гра постійно пише технічні логи у файл `output_log.txt` на диску. Софт у реальному часі читає цей файл, миттєво перехоплюючи дані про нанесення шкоди (Combat Log).
  - *Переваги:* Виводить на екран точну інформацію: хто поцілив, куди (голова/тіло), з якої відстані та скільки точного HP залишилося у ворога за частки мілісекунди до того, як це відобразиться в офіційній консолі гри.

* **Моніторинг системних івентів через Windows Event Tracing (ETW)**
  - *Суть:* Використання вбудованої підсистеми логів продуктивності Windows.
  - *Реалізація:* Коли сервер гри надсилає на ПК пакет про зміну стану об'єктів світу (хтось відкрив двері, підірвав стіну, вистрілив), Windows фіксує цей мережевий івент у системи ETW. Чит реєструється як легальний монітор продуктивності (Performance Monitor) і слухає цей потік.
  - *Переваги:* **Ідеальний інструмент для софту під HvH (Hack vs Hack).** Дозволяє миттєво знати про кожну дію супротивника крізь усю карту без затримок та малювати динамічні маркери подій.

## 🗑 Категорія 6: Розділ «Смітник» (Застарілі та непрактичні методи)
* **Test Mode / Insider Preview:** Повністю заблоковано EAC у Rust на етапі запуска гри.
* **Підміна сертифікатів через Реєстр:** EAC ігнорує реєстр Windows і використовує свій жорсткий внутрішній білий список підписів.
* **Модифікація NVRAM/ACPI:** Рівень розробки під конкретні мікросхеми живлення плат; занадто нестабільно та небезпечно (є ризик перетворити ПК на цеглину).
* **Asset/Pak Hacking (Заміна текстур на диску):** Миттєвий бан до головного меню через жорстку перевірку контрольних суми (Хеш SHA-256) усіх файлів гри перед стартом.

* **vDMA / Програмна емуляція PCIe** (Додати в Категорію 1)
  - *Суть:* Обман шини PCIe без купівлі фізичної DMA-плати.
  - *Реалізація:* Чит використовує вразливість у драйвері чипсета материнської плати (наприклад, Intel Management Engine або AMD PSP) і через технологію IOMMU (Intel VT-d) змушує процесор думати, що всередині ПК працює легальний віртуальний пристрій PCIe з прямим доступом до ОЗУ.

* **UEFI Bootkits (Хакінг завантажувача)** (Додати в Категорію 2)
  - *Суть:* Перехоплення повного контролю над системою до старту захисту Windows.
  - *Реалізація:* Код читу прописується в розділ EFI на жорсткому диску замість стандартного завантажувача Windows. Він модифікує ядро операційної системи (`ntoskrnl.exe`) безпосередньо в ОЗУ до того, як воно почне виконуватися і запустить сервіси античиту.

* **ELAM Bootkits (Early Launch Anti-Malware)** (Додати в Категорію 2)
  - *Суть:* Запуск читу на ультимативному етапі раннього старту антивірусів.
  - *Реалізація:* Чит маскується під офіційний антивірусний драйвер раннього завантаження (ELAM), який має найвищий рівень довіри від Microsoft. Він запускається в мить, коли ядро Windows тільки з'явилося в пам'яті, повністю контролюючи подальше розгортання самого сервісу EAC.

* **WinPcap / Npcap Локальний Packet Sniffing** (Додати в Категорію 4)
  - *Суть:* Мережевий «двійник» на одній машині без використання сторонніх роутерів чи телефонів.
  - *Реалізація:* На ігровий ПК встановлюється офіційний системний драйвер для аналізу мережевих пакетів (Npcap), який копіює весь інтернет-трафік від сервера гри. Окрема програма-чит розшифровує цю копію пакетів і дізнається координати об'єктів, взагалі не контактуючи з процесом гри чи її ОЗУ.

* **Proxy DLL / DLL Hijacking** (Додати в Категорію 4)
  - *Суть:* Підміна легальних файлів гри безпосередньо на етапі запуску.
  - *Реалізація:* Чит перейменовується на ім'я легальної системної бібліотеки або модуля Unity (наприклад, `version.dll` або `winmm.dll`) і підкидається в кореневу папку гри. При старті гра сама завантажує код читу, вважаючи його своїм рідним компонентом.

* **JIT-компіляція Unity / Експлойт компілятора** (Додати в Категорію 5)
  - *Суть:* Модифікація логіки гри на етапі збірки машинного коду «на льоту».
  - *Реалізація:* Чит не чіпає пам'ять процесу гри, а вбудовується в сам JIT-компілятор Unity (або механізми обробки IL2CPP). Інструкції змінюються безпосередньо в момент їх генерації процесором ПК, що робить класичну перевірку цілісності статичних файлів безсилою.
