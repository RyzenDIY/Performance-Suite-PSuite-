RustVision — идеи и ТЗ для Claude

ВАЖНО
Проект делаем как самостоятельное Windows/WPF-приложение без привязки к Rust:
- без DLL injection;
- без чтения/записи памяти игр;
- без обхода античита;
- без автоматического наведения/ESP/No Recoil;
- без функций, которые дают преимущество в сетевой игре.

Цель: premium system monitor + optimizer + PSuite с качественным gaming UI.

17. КРИТИЧНО ДЛЯ CLAUDE
Пиши украинским языком.

Не оставляй пустых файлов.
Не оставляй TODO вместо реализации.
Не пиши «остальной код без изменений».
Каждый созданный файл должен иметь полный рабочий код.
Namespace, x:Class и ресурсы должны совпадать.
Все кнопки должны быть подключены.
XAML должен собираться.

Если модуль еще не готов — сделать минимальную рабочую реализацию, а не пустой файл.

18. SINGLE INSTANCE
RustVision должен запускаться только в одном экземпляре.
При повторном запуске:
- не создавать второе окно;
- активировать уже открытое;
- вывести его на передний план.

Использовать Named Mutex.

19. ПРОИЗВОДИТЕЛЬНОСТЬ
Не создавать десятки DispatcherTimer.
Использовать один scheduler/async background monitoring.
UI обновлять через Dispatcher.
Корректно останавливать timers, CancellationToken и события при закрытии.
